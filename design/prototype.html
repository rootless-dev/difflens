Adds the refund flow

A new POST /refunds endpoint backed by a new refund package. It loads the payment, validates the amount against what is still refundable, calls the payment gateway and stores the refund. payment.Repo now exposes the refundable balance, and storage gains a refunds table.

What the card asks

Allow refunds for settled payments

PAY-482 PR #318

Support wants to refund a settled payment, in full or in part, without opening a ticket with the provider. A refund must never exceed what was paid, must survive a retry, and finance has to be told about each one.

Refund can be paid out and never recorded

internal/refund/service.go:52

The gateway refund runs first and the row is saved afterwards. If Save fails, for instance on a database timeout, the customer has the money back and the system has no refund on record. A retry would then refund a second time.

52 ref, err := s.gateway.Refund(ctx, p.ChargeID, amt)
53 if err != nil {
54 return fmt.Errorf("gateway refund: %w", err)
55 }
56 return s.refunds.Save(ctx, Refund{PaymentID: id, Ref: ref, Amount: amt})

You confirmed this on 12 Nov. The code around it changed since then, so check it again.

Suggested direction

Save the refund as pending before calling the gateway, then mark it completed or failed with the gateway's answer.

What shows itread from the code, not reproduced

  • Line 52 asks the gateway to refund; line 56 stores the refund only after that.
  • When Save returns an error the function just returns it. No path undoes the refund or records it elsewhere.

Related, but not proof

  • No test makes Save fail, so this path has never been run.
